# 자유게시판 적용·확인

## 적용

Supabase SQL Editor에서 `42_board.sql` 전체를 실행한다. 기존 01~41 적용이 선행 조건이다.
SQL은 트랜잭션으로 구성되어 실패하면 전체 롤백된다. 재실행해도 게시글은 보존된다.
직접 실행하지 않는 프로젝트 규칙에 따라 개발 중 운영 DB에는 적용하지 않았다.

## 화면 및 권한 확인

| 사용자 | 기대 동작 |
| --- | --- |
| 비로그인 | 목록·검색·상세·댓글 읽기 가능, 작성 화면은 로그인 안내 |
| 로그인·미인증 | 읽기 가능, 글/댓글 작성은 교사인증 안내, API 직접 작성도 거절 |
| 인증 교사 A | 글/댓글 등록, 자신의 글/댓글 수정·삭제 가능 |
| 인증 교사 B | A의 글/댓글 수정·삭제 거절, 답글·신고 가능 |
| 운영진 | 게시글 고정·고정 해제·삭제 가능, 타인 본문 수정 불가 |
| 인증 회수된 A | 새 글/댓글 및 수정 거절, 자신의 글/댓글 삭제 가능 |

1. 인증 교사로 제목과 본문을 등록하고 새로고침 후 보존을 확인한다.
2. 빈 제목·빈 본문은 저장되지 않아야 한다. 본문 이미지 작업 중 등록 버튼은 비활성이다.
3. 16개 이상 등록한 환경에서 다음/이전 페이지, 검색, 검색 초기화, 브라우저 뒤로가기를 확인한다.
4. 서로 다른 두 게시글의 댓글끼리는 답글 연결이 거절되어야 한다(API 포함).
5. 글 삭제 후 주소 직접 접속은 찾을 수 없음, 댓글 조회·새 댓글 작성도 차단되어야 한다.
6. 댓글·답글·멘션·댓글 좋아요 알림이 올바른 `/board/:id`로 이동하는지 확인한다.
7. 게시글 신고가 운영진 신고 큐에 나타나고 ‘게시글 확인·삭제’ 링크가 열리는지 확인한다.
8. 차단한 사용자의 글은 목록과 직접 접근에서 표시되지 않는지 확인한다.
9. 앱·수업실천사례의 기존 댓글 작성·답글·수정·신고·알림도 회귀 확인한다.

## DB 권한 확인 시 주의

SQL Editor의 관리자 계정은 RLS를 우회하므로 관리자 SELECT 성공만으로 권한 검증을 끝내지 않는다.
위 각 계정의 실제 로그인 세션으로 REST/RPC를 호출해 허용·거절을 확인한다.
`posts` 직접 INSERT/UPDATE/DELETE는 모두 거절되어야 하고, 쓰기는 제공된 RPC로만 가능해야 한다.

## 개발 시 확인한 범위

- TypeScript 및 프로덕션 빌드
- 린트(기존 경고 별도)
- DB 미적용 상태의 연결 안내, 비로그인 글쓰기 차단, 잘못된 글 주소 안내
- 실제 데이터 저장 및 역할별 DB 검증은 SQL 적용 후 필요

권한 설계 참고: https://supabase.com/docs/guides/database/postgres/row-level-security


## 2026-10-27 SQL 적용 후 실제 DB 검증

`tests/board_permissions.sql`을 연결된 프로젝트에서 실행했다. 관리자 SELECT 결과로 판정하지 않고,
트랜잭션 내 `SET LOCAL ROLE anon/authenticated`와 각 회원의 JWT sub로 실제 RLS·RPC를 검사했다.
모든 데이터 변경은 ROLLBACK했고 테스트 게시글과 알림이 0건인 것도 확인했다.

통과한 16개 검증 묶음:

1. 인증 교사 글 작성 및 작성자 일치
2. 본인 글 수정 및 저장값 일치
3. 빈 제목·빈 본문 거절
4. posts 직접 INSERT/UPDATE/DELETE 거절
5. 일반회원 상단 고정 거절
6. 본인 댓글 작성·수정
7. 타인 글·댓글 수정/삭제 거절
8. 댓글 작성자 위조 거절
9. 정상 답글 허용, 다른 글 답글·2단계 답글 거절
10. 댓글·답글 알림과 게시글 이동 경로
11. 미인증 회원 읽기 허용, 글·댓글 작성 거절
12. 비로그인 읽기 허용, 글·댓글 작성 거절
13. 운영진 고정/해제·글/댓글 삭제 허용, 타인 본문 수정 거절
14. 본인 댓글 삭제, 이미 달린 답글 보존
15. 삭제된 댓글에 새 답글 거절
16. 본인 게시글 삭제, 글과 댓글 조회 차단, 새 댓글 거절

브라우저: SQL 적용 뒤 비로그인 목록이 오류 없이 `전체 글 0개`로 표시되는 것 확인.
로그인 후 로컬 브라우저에서 실제 화면 테스트도 완료했다.

- 글 등록 → 제목·본문 수정 → 새로고침 후 보존 확인
- 댓글 등록 → 댓글 수정 → 새로고침 후 보존 → 댓글 삭제
- 목록 반영 및 제목 검색 1건 반환 확인
- 글 삭제 → 목록 0건 → 삭제된 글의 직접 주소에서 찾을 수 없음 확인
- DB 재조회로 제목·본문·댓글 수정값, 글/댓글 deleted_at을 확인
- UI 테스트 글 1개와 댓글 1개는 정상 소프트 삭제됨. 이 테스트로 생성된 알림은 0건.

실제 UI 테스트 계정은 인증된 관리자였으며, 일반 인증교사·미인증·비로그인·타인 권한 차이는 위 DB 역할 테스트로 별도 확인했다.
추가 수정이 필요한 오류는 발견하지 못했다.
인증 회수 시나리오, 이미지 업로드, 다량 데이터 페이지 이동 및 앱/사례 댓글 회귀 테스트는 이 실행에 포함하지 않았다.

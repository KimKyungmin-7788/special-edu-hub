# 안내 메일

회원이 가입하고 교사인증을 받는 각 단계에서 자동으로 보내는 메일을 정리한 문서다.
문구를 고칠 때는 이 문서와 `src/config/email.ts`를 **함께** 고친다. 실제로 나가는 문구는 코드(`email.ts`)가 기준이다.

- 기록 시점: 2026-10-30
- 관련 파일: `supabase/47_email_notifications.sql`(언제 보낼지), `api/send-email.ts`(발송), `src/config/email.ts`(문구)

## 3. 문구 고치는 법

| 고칠 것 | 위치 (`src/config/email.ts`) |
|---|---|
| 누리집 소개 문단(① 가운데) | 맨 위 `mission` |
| 공통 꼬리말 | `devNote` 함수 |
| 각 메일 제목·본문 | `templates` 안의 `welcome`, `verify_received`, `verify_approved`, `verify_rejected`, `staff_new_request` |
| 누리집 이름·주소·연구회 이름 | `src/config/site.ts`의 `name`, `url`, `org.name` |

공식 도메인을 열면 `site.ts`의 `url`과 `index.html`의 canonical 주소를 바꾸고, 보내는 주소를 새 도메인 메일로 옮긴다.
그때 공통 꼬리말의 "개발 단계" 안내도 빼거나 고친다.

## 4. 처음 설정 (한 번만)

1. 운영자 구글 계정에서 2단계 인증을 켜고 **앱 비밀번호**(16자리)를 만든다.
2. Vercel 환경변수를 넣는다.
   - `GMAIL_USER` = 보내는 지메일 주소
   - `GMAIL_APP_PASSWORD` = 1번의 앱 비밀번호
   - `EMAIL_WEBHOOK_SECRET` = 남이 짐작할 수 없는 긴 문자열(30자 이상)
   - `EMAIL_ADMIN_TO` = (선택) ⑤ 운영자 알림을 받을 주소. 비우면 `GMAIL_USER`로 간다.
3. `main`에 합치고 배포한다.
4. Supabase SQL Editor에서 `supabase/47_email_notifications.sql`을 실행한다.
5. SQL Editor에서 한 번만 실행한다.
   ```sql
   select vault.create_secret('https://special-edu-hub.vercel.app/api/send-email', 'email_webhook_url');
   select vault.create_secret('<EMAIL_WEBHOOK_SECRET 과 같은 값>', 'email_webhook_secret');
   ```
6. 다른 이메일로 가입해 ①이 오는지, 교사인증을 신청해 ②와 ⑤가 함께 오는지 확인한다.

5번을 하기 전에는 메일을 보내지 않고 조용히 건너뛴다.

## 5. 알아 둘 점

- 개인 지메일은 하루 약 500통까지 보낼 수 있다. 개인 안내 메일에는 충분하다.
- 메일이 안 오면 `email_log`(요청 기록)와 Supabase의 `net._http_response`(서버 응답), Vercel 함수 로그를 차례로 본다.
- 개인정보처리방침에 Google(지메일) 위탁과 안내 메일 발송 목적을 적어 두었다. 보내는 항목이 늘면 방침도 함께 고친다.

## 6. 다음에 할 것

- **공지·뉴스 메일**: 여러 회원에게 한꺼번에 보내는 메일. 가입 때 받기 동의(선택)를 받고, 메일마다 받기 거부 링크를 붙여야 한다.
  연수방 소식도 여기에 해당한다.
- **공식 도메인 개설**: 보내는 주소를 `noreply@도메인` 등으로 옮기고 개발 단계 안내를 정리한다.
